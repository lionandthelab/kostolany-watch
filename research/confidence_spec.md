## 0. 지배 원칙 (모든 하위 결정에 우선)

1. **단일 출처 원칙** — 화면의 모든 %는 오직 한 경로로만 생성된다: 아티팩트 셀 → `calibration.py` 전사 상수 → payload → 프론트 `pctFloor()`. i18n 문자열에 % 숫자 하드코딩 금지(모든 숫자는 `{p}` 슬롯 주입).
2. **과거 빈도 + 상태 소속 화법** — K7(`confidence_is_calibrated=False` 영구, calibration.py:20)에 따라 미래 확률 화법(「~일 확률 N%」) 전면 금지. 모든 수치는 「과거 ~였던 날: 실측 N%」(과거형 빈도) + 「현재 레그 소속」(전진 방향 예측 아님) 형태로만 서술한다. 63일 전방 방향 스킬은 0으로 실측되었다 — 방향 예보로 읽히는 문장은 그 자체가 허위다.
3. **내림(floor) 전용 표기** — 0.8062→80%, 0.6748→67%, 0.8771→87%, 0.245→24%. 올림·반올림 절대 금지. 카드에는 정수, 측정 방법 서랍에서만 소수 1자리(0.1% 단위 내림).
4. **투표는 카운트, 확률은 조회** — 라이브 8규칙 투표는 결정론적 카운트다. 카운트를 자체적으로 확률로 변환하지 않는다. 모든 확률은 저장된 조건부 테이블 조회다(파라미터 0개 → "무학습 헤드" 주장 유지).
5. **티어 비닝 동결** — 8-0 / 7-1 / 6-2 / 분열(5-3·4-4) 구분은 아티팩트에 동결된 그대로. 표시 결과를 보고 재비닝하면 selection에 의한 fitting이므로 금지(비협상).
6. **모집단 라벨 원칙** — 티어 조건부 문장 안에는 그 티어 셀의 숫자만 들어간다. 무조건부 숫자는 반드시 「전체 거래일 기준」 라벨과 함께만 등장한다. 교차 조건 혼합 금지.
7. **기본 화면 숫자 예산: 2개** — 헤드라인 카드에 보이는 %는 방향(티어 조건부) 1개 + 위치 ±1칸(전체 기준) 1개. 나머지 전부 접이식.

### 2.2 스냅샷 투표 블록 — momo 헤드 전용

`momo.py`에 신설:

```python
RULE_IDS = ("ma20", "ma40", "ma60", "ma100", "ma200", "ret10", "ret20", "ret60")

def rule_votes(self, prices: pd.Series) -> pd.DataFrame:
    """Per-rule UP votes (bool), one column per RULE_IDS. Causal, zero parameters.
    Column sum must equal vote_counts()."""
```

`EngineSnapshot` → `SnapshotResponse`에 optional 필드 `vote` 추가(momo만, AI 헤드는 `null`):

```json
"vote": {
  "up": 0, "down": 8,
  "split": "8-0",
  "tier": "unanimous",          // max(up,down): 8→unanimous, 7→strong, 6→lean, else mixed
  "side": "down",               // up if up >= 4 (tie→UP, momo.py:80의 사전 규칙 그대로)
  "rules": [{"id": "ma20", "vote": "down"}, ...]   // 8개, RULE_IDS 순서 고정
}
```

**정합성 트랩(치명, 리뷰3 검증):** 투표는 **두 momo 생성 경로 모두**(engine.py의 `fit_analyst_bundle` 경로와 `/snapshot`·`/watch/one` 단일 모델 경로)에서 채워야 하며, 서빙 regime과 동일하게 `reindex(X.index).ffill()` 정렬해야 한다(engine.py:315 패턴). 정렬 후에도 `vote.side ≠ 호출된 momo regime의 side`인 봉이 나오면 **fail-closed**: `vote`를 null로 내보내고 로그 — UI는 자동으로 카운트 배지를 숨긴다. 화면에서 「8개 중 5개 하락」 배지 옆에 상승 콜이 뜨는 모순은 어떤 경우에도 불가.

**▸ 이 숫자는 어떻게 쟀나요? (소수점은 여기서만):**
```
· 모든 %는 워크포워드 표본외 구간에서 금본위 라벨로 채점한 과거 빈도입니다.
  미래 확률이 아니며, 미래 수익·가격 방향을 예측하지 않습니다.

  (코드와 함께 보관, 2026-07-30 산출)
· % 표기는 항상 내림입니다 (예: 0.8771 → 87%).
· 정렬 등급은 방향 적중과만 뚜렷이 동행합니다. 정확 칸 적중은 정렬과 무관하게
  평평해서(^GSPC 23~26%, BTC-USD 20~28%), 등급은 방향에만 적용합니다.
· 헤드라인 판정은 학습된 모델이 아닙니다. 표시 확률의 최대값(약 25%)은 측정된
  정확 칸 적중률과 일치하도록 고정되어 있습니다.
· 정밀 참고: 레그 내 위치 적중(실측 36.1%)은 구조상 상한 37.2%에 근접해
  있습니다 — 남은 격차는 위치가 아니라 방향 쪽에 있습니다.
```
(BTC: 34.6%. 넷째 줄이 티어-조건부 exact의 평평함/비단조를 **정면 공개** — BTC 만장일치 20% 포함 — 체리피킹 공격 차단. 상한 문장에 「실측으로 확인」 금지: 구조상 상한이다.)

### 3.3 달걀 (EggChart.tsx + eggGeometry.ts)

레이어 (아래→위). **circularSpread 호와 momo 사후분포는 무변경. 달걀에 %를 그리지 않는다.**

1. **사이드 밴드(신규)** — 콜 사이드 3칸 집합(상승={A1,A2,A3} / 하락={B1,B2,B3})을 잇는 림 밴드. 불투명도는 **4단 이산 계단** `{unanimous: 0.26, strong: 0.18, lean: 0.10, mixed: 0}` (디자인 상수 = 등급 서열 표시이지 측정값 아님 — 범례에 명시). 혼조 날은 사라진다: 달걀이 눈에 띄게 "사이드 콜 없음"을 말한다. 연속 알파 금지.
2. **존 밴드(신규)** — 판정 칸 ±1(링 순서 A1→A2→A3→B1→B2→B3→A1 기준 3칸), 고정 저불투명 림 밴드. 콜이 사이드 중앙 칸이면 사이드 밴드와 집합이 일치 — 존 밴드를 위에 그대로 겹쳐 렌더(중복 무해).
3. **기존 사후분포 호 + 핀** — 무변경, 최상단. **이 호에 ±1 커버리지 숫자를 붙이는 것은 영구 금지** (가변폭 호에 고정 ±1칸 측정을 붙이면 날조된 대응 — 리뷰 만장일치 결함).

기하: `REGIME_ANGLE`(eggGeometry.ts:7)은 불균등 점 각도뿐이므로 **신규 코드**로 인접 각도의 원형 중점 = 칸 경계를 계산하고, 기존 rim 함수로 경계~경계 폴리라인 밴드 패스를 생성한다("기존 sector 헬퍼 재사용" 주장은 전 설계 공통 허위였음 — 존재하지 않는다). 링 재배치는 하지 않는다.

범례 (달걀 아래 1줄): 「짙은 호 = 오늘의 판정 범위 · 옅은 띠 = 판정 ±1칸 · 물결 = {하락} 레그 쪽 3칸(B1·B2·B3), 진하기는 정렬 등급 표시(수치 아님)」 — 「반원」 표현 금지(상승쪽 ≈217°, 하락쪽 ≈143°라 기하학적 허위). 집합은 항상 칸 이름으로 명명.

### 3.4 AI 참고 패널

합의 배지 유지하되 재라벨: 「참고: AI 3종 교차검토 — 합의 {code} · {k}/4」. 은퇴한 확신 밴드 어휘는 이 패널 내부에서만 사용 가능. 카피 고정: 「기본 판정은 AI가 아닌, 사전 등록된 8개 추세 규칙의 다수결입니다. AI 시점(HMM·GBM·TSFM)은 참고용입니다.」

### 3.5 i18n (ko.ts / en.ts / types.ts)

신규 네임스페이스 `conviction.*`: `badge.{unanimous,strong,lean,mixed}`, `side.{aligned,mixed}`, `tieNote`, `zone`, `ladder.{title,direction,zone,exact,exactWhy}`, `tierTable.{title,colTier,colSide,colShare,footer}`, `ledger.{title,rules.ma20…ret60,footer}`, `method.{title,l1…l6}`, `egg.legend`, `unmeasured`, `aiRef.{title,note}`. en.ts는 동일 의미(과거 빈도 + 레그 소속)를 영어로 미러 — "probability of being/going" 금지, "of past days with this alignment, N% were in a down leg (measured)" 문형. 모든 템플릿은 `{n}`/`{p}`/`{side}`/`{regime}` 슬롯.

## 6. UI가 절대 렌더하지 않는 문장 (금지 목록 — 테스트로 강제)

1. 「확신도 N%」 및 momo 헤드라인의 「확신 낮음/중간/높음」 (밴드 어휘는 AI 패널 한정)

4. 다른 모집단 숫자가 라벨 없이 들어간 티어-조건부 문장 (예: 「이 정렬 상태에서 ±1칸 64%」)

7. 아티팩트에 없는 파생 숫자: 「상한 대비 70% 수준」 등 비율 주조 일체

9. 올림된 수치 일체: 81%(0.8062), 68%(0.6748), 88%(0.8771), 25%(0.245)
10. 타 심볼 수치·하드코딩 % (모든 숫자는 조회 중인 심볼의 payload에서만)
11. 무측정 심볼의 어떤 적중률
12. 「반원」·「반구」 (집합은 「B1·B2·B3」처럼 칸 이름으로)
13. 자문 어휘: 「권고」 「전략입니다」 「매수/매도/관망하세요」
14. circularSpread 호에 부착된 커버리지 숫자
15. 「레그/방향」 단어가 같은 구에 없는 사이드 % (사이드 %와 국면 코드 병치 금지)
16. 「동전 던지기」 직유의 공용 템플릿 (심볼별 값 55%/60%가 갈리므로)
17. 확률이 보정되었다는 어떤 암시 (`confidence_is_calibrated`는 영구 False)
